# Design & architecture decisions

NOOP's project memory: the durable record of *why*, so a question settled once isn't re-litigated
later. This covers the whole project, not just the redesign — architecture choices and their
rationale, ideas deliberately rejected, known tech debt, and planned future stages — so a session can
answer "why is X built this way" or "what's worth improving" by reading this file instead of
reconstructing it from git log or commit history. Its entries below happen to all be redesign-dated
so far, but that's a starting point, not a scope limit; add non-redesign decisions here too rather
than starting a separate file (see [`CLAUDE.md`](../CLAUDE.md) § Documentation & session workflow).
One row per decision. Supersedes any conflicting rows in `redesign-prompts.md` (the original handoff
doc, kept for its screen specs but written against an upstream-close fork whose assumptions no longer
hold).

| Date | Decision | Why |
|---|---|---|
| 2026-07-23 | iOS/macOS-only; stop necessarily tracking upstream | Android target dropped; the fork is 779 commits ahead / 0 behind and diverges freely now |
| 2026-07-23 | Cross-platform parity contract (byte-identical analytics, FNV-1a hashing, Room/GRDB agreement) is **retired** | No Android reimplementation to stay in sync with. Offline / no-server / no-account / anonymous constraints are separate and still binding |
| 2026-07-23 | Redesign evolves existing shared screens + Palette **in place** (not additive new files under StrandiOS/Redesign/) | StrandDesign is already forked (gold→blue); screens are shared Strand/ code; LiquidTodayView already implements the mockup's core. Additive files would duplicate shared logic and stand up a second redesign |
| 2026-07-23 | Briefing palette (green Charge / blue Effort / violet Rest / gold Longterm) ships as a **new selectable `ChartStyle` ("Signature"), defaulted on** | Reuses the frozen-token re-theme pattern; leaves the 6 existing chart styles intact; only recolors data encodings, never chrome |
| 2026-07-23 | Languages: **EN (source), DE, FR, ES** | Usage is multilingual; English stays the source-of-truth locale |
| 2026-07-23 | Effort ring max is **user-selectable 0–21 or 0–100** | Already built (`EffortScale`, Settings picker); ring must reflect the chosen scale, not just the printed number |
| 2026-07-23 | System surface (WidgetKit, Live Activity/Dynamic Island, App Intents-Siri) pulled into scope | iOS strength unblocked by dropping Android parity |
| 2026-07-23 | iOS 26 Liquid Glass as a consistent design language (`glassEffect`, nav-zoom, Material) | Builds on the existing Liquid layer; applied during screen cleanups |
| 2026-07-23 | On-device Foundation Models coach — **deferred** | Svea stays on the current local engine (`Strand/AI/AICoach.swift`) for now; revisit later |
| 2026-07-23 | Accelerate/vDSP analytics rewrite — **deferred** | Validated physiological math; a rewrite must re-prove against the artifact. Left untouched to keep risk low |
| 2026-07-24 | Heute redesign carries data through the **shared** carry-over selectors (`TodayView.lastScoredRecoveryDay` + `LiquidTodayView.ChargeDisplay`, `Repository.lastVitalsDay`/`lastSpo2Day`), not its own generic "latest value ≤ day" fallback | Heute used one rule for everything (Charge, Effort, vitals) and could show a different number than Liquid/classic for the same day; composing the same selectors makes all three agree and shows the honest "Calibrating" state mid-baseline. `LiquidChargeCarryTests`' "cannot drift" rule now covers Heute too |
| 2026-07-24 | `VitalTileConfig` (Heute) and `KeyMetric`/`KeyMetricPrefs` (Liquid/classic) are **NOT unified** | Two parallel configurable-tile persistence systems, but merging them is a separate, riskier data refactor (migration + catalog reconciliation). Left as-is; only the *value* selectors were shared |
| 2026-07-24 | ActivityStatus (Sick/Injured/On break) is **cross-screen**: a shared `StrandPalette` sheet (`SharedActivityStatusSheet` + `ActivityStatusChipCompact`, `Strand/Screens/`) on Liquid + classic; Heute keeps its own `HeuteRedesignPalette` sheet | The status data model was always screen-neutral; only the UI was Heute-bound. A set exception status overrides the base/synthesis statement on all three, even during calibration (an explicit user statement wins). Heute's fork-palette sheet can't be reused, so the shared one is a second skin, not a replacement |
| 2026-07-24 | Liquid's `synthesisCard` expand is an **`.onTapGesture`, not an outer `Button`** | The status chip is itself a Button; a Button nested in another Button's hit-test tree doesn't reliably receive taps (documented at `HeuteVitalsGridView`). Cost: the card's `LiquidPressStyle` press-scale is dropped (reproducing it needs a 0-distance drag that fights day-swipe/scroll) |
| 2026-07-24 | Heute suggestion cards are fed by **`CoachPlanStore.pending`** (the coach's `propose_plan` proposals), display-only — the placeholder `sampleCards` is gone (D-package 2) | The real source already existed and is what Liquid/classic surface; Heute only surfaces, never generates. Suppressed by `ActivityStatus.suppressesTrainingSuggestions`. Mapping/store live in `Strand/Data/HeuteSuggestion.swift` (with `NotificationCardItem` moved there) so they're macOS-testable like the other shared data types |
| 2026-07-24 | Swiping a Heute suggestion card is a **local hide (persisted id set), NOT a `declined`** | A casual swipe must not feed `CoachPlanStore.declineStreak` / the filter-bubble floor. The formal accept/modify/decline lives in `CoachPlanView`, opened by tapping the card. Vitals-anomaly as a second card source stays out (no detector exists) |
| 2026-07-24 | The Charge-breakdown driver composition is extracted into the shared pure `ChargeBreakdownFormat.compute(row:days:restScore:)`, called by both classic `TodayView.chargeBreakdown()` and Heute (D-package 3) | Tapping the Charge ring on Heute now opens the same "what shaped it" drivers the other two Today screens show. Composing them once (fold HRV/RHR/resp baselines → `RecoveryScorer.chargeDrivers` + `ScoreConfidence.charge`) means the two callers can never describe the same day differently — the P5 shared-selector principle, now unit-pinned by `ChargeBreakdownFormatTests.testComputeMatchesTheEngineCompositionVerbatim` |
| 2026-07-24 | Only the **Charge** ring is tappable on Heute; the breakdown sheet is Heute's own `HeuteRedesignPalette` skin (`HeuteChargeBreakdownView.swift`), not the classic `ChargeBreakdownSection` | Effort/Rest ring taps + a scoring guide for all three were the broader, unchosen option. The classic sheet is `StrandPalette`/`StrandFont`-styled and uses chart-style-dependent chip colours; Heute needs fixed green/red tokens, so the sheet is a port (same shared `compute`, same pure format helpers), not a reuse — the same pattern as `HeuteHeartRateView`. Deep-window-gap (#233) and the folded Readiness/scoring-guide blocks stay classic-only |
| 2026-07-24 | Heute's Kopfzeile→Ringe spacing (design-spec §5) reverted from the deliberately-tight 2pt to 18pt; Ringe→Kartenzone raised 24pt→30pt alongside it | On-device feedback read the 2pt gap as cramped, not "belonging together" as originally designed — supersedes that row's own "(bewusst eng...)" rationale. The second gap was raised too so the spacing table keeps a coherent rhythm around the change, not just one isolated row |
| 2026-07-24 | Weight write-back (`ProfileStore.weightKg` → Apple Health) and "Health always wins" read-back (every sync overwrites the profile field, not just once when unset) both wired, unconditionally | User decision, reverses `HealthKitBridge`'s prior "(#20) we never write these back" stance for weight specifically (body-fat/lean-mass/BMI stay read-only). Known tradeoff: a manual profile edit not yet written back to Health (e.g. app killed mid-write) can be reverted by the next sync's "Health always wins" read — accepted explicitly, not engineered around with a "pending write" flag |
