# NOOP AI 11.8.3

This release integrates the applicable Apple changes from RyanBR upstream while preserving the
Apple-only fork, its whole-tree localization gate, and its Coach and Today redesign.

## Reliability and honest readouts

- Older live GPS workouts saved under the canonical workout owner are now included in the resumable calorie repair. When the later strap offload differs from the live recording, NOOP also checks the saved live average heart rate and moving duration before replacing a legacy computed value. Calories already marked as manually entered remain untouched. A failed device-registry or heart-rate read keeps the repair pending for retry. Analysis migration required: yes — recipe AI-14 retries the session correction for installs already at AI-13; it does not rescore daily analysis rows.
- The session calorie repair now reads each day's resting heart rate from NOOP's own daily rows as well as imported ones. AI-13 and AI-14 saw only imported rows, which end at the last WHOOP export, so they recognised and re-priced sessions without a resting rate: some old Keytel figures stayed (a 3,471 kcal walk), and the ones they did replace were priced on the wrong inputs. Sessions already marked as computed are priced again; entered figures remain untouched. The same resting-rate read feeds the calorie estimates in the Workouts list, the workout detail, the Coach and Training Load. Analysis migration required: yes — recipe AI-15 runs the session correction again; it does not rescore daily analysis rows.
- A new energy model now recomputes the stored energy history once, in the background, instead of only today and freshly synced days. Every multi-day energy recompute had been failing on a bucket filed under two days, so older days kept superseded rows (some with a single bucket and a near-zero total) and fell back to the retired whole-day estimate.
- An Apple Watch VO₂max reading now counts for six months instead of 30 days, converted from the weight at the time of the reading to the current one. With a rarely worn Watch, workouts priced by heart rate had fallen back to a population estimate that read almost twice the measured value.
- Apple Health workouts now show average and peak heart rate, Effort and steps. The heart rate comes from the band where it covered the session, otherwise from the workout's own Apple Watch minutes, and the detail screen says which. Older workouts are read in the background, newest first, and their training load is recalculated where a heart rate is now available. Workouts the WHOOP app copied into Health keep their empty fields. Analysis migration required: yes — recipe AI-16 fills stored Apple Health workouts; it does not rescore daily analysis rows.
- The Workouts list reloads when stored session energy changes, and the workout detail shows its route, steps and a recorded calorie figure before the heart-rate charts finish loading.
- Interrupted background reanalysis is retried after its cooldown and paced in short CPU quanta.
- Charge details, confidence labels and Coach summaries use the same post-recalibration HRV history.
- On re-signed installations, the first Backup & Sync folder pick no longer forces the app's own
  Documents container as its starting point. Files now chooses its normal location, while a previously
  granted external folder remains available as a start hint.
- Alarm screens distinguish the strap's actual wake alarm from the evening reminder and show the
  countdown to the next buzz.
- A still-growing detected night and its vitals are held out of Apple Health until the night closes.
- Oura authentication retries an unanswered nonce within a bounded watchdog, and the Live console
  reports the ring's actual connection phase.
- Strap rename diagnostics no longer print the user-chosen Bluetooth name.

## Lab Book continuity

Custom count and percentage rows such as `LYMPH` and `LYMPH %` now receive distinct keys. On upgrade,
the versioned migration identifies legacy custom rows whose stored unit is explicitly percent, moves
them to the percentage key, rebuilds their daily projections in the same transaction, and advances its
cursor only after success. Count rows, user-entered readings, sleep/workout corrections and raw samples
are not erased.

Analysis migration required: yes. Recipe 8 performs the Lab Book key migration and then runs the
resumable bounded 21-day analysis pass so recent consumers of the old projected key are refreshed.

## Claude follow-up integration

- The latest same-night SpO₂ estimate now outranks a stale reading, and the weight ring accommodates
  three-digit values without clipping. Analysis migration required: no; stored values and scoring math
  are unchanged.
- Charge-band tests now assert the semantic bands rather than translated labels, and the new
  weight/energy UI copy is complete in every shipped locale. Analysis migration required: no; these are
  test and presentation changes only.
- Update checks, the About screen, support links and release tooling now resolve through this fork's
  `DX23876/noop` endpoints rather than upstream. Analysis migration required: no; repository routing does
  not change health data or derived values.
